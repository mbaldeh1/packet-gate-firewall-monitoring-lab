What the preset rule sets teach

Wide open

Everything is allowed, so every scan and brute-force attempt reaches the server. This is where many first-time deployments start.

Block-list only

You block known bad ranges and allow the rest. It stops those attackers but misses the next new address, so it is a weak design.

Default deny

You allow only what the server needs and drop everything else. This is the standard approach, and it scores best here.

Export to a real firewall

The exporter builds a dedicated custom chain instead of flushing the existing INPUT chain or changing its global default policy. Review every command and test on a lab machine before applying.

Project scope and limitations

Implemented in this browser demo: ordered allow/block rules; source and destination IPv4/CIDR matching; protocol, destination-port and connection-state matching; deterministic synthetic attack scenarios; browser-side unit tests; Suricata EVE JSON and Zeek conn.log import; heuristic alerts; JSON rule import/export; CSV alert export; and generation of a reviewed Linux iptables ruleset.

Not implemented: packet capture, kernel firewall control, a live connection to Suricata/Zeek, automatic sensor deployment, automatic firewall changes, authenticated administration, persistent server-side storage, IPv6 matching, or production-grade intrusion detection. Alert thresholds are teaching heuristics, not validated detection models.

Data handling: rules, imported logs and alerts are processed in the browser. Imported files are not uploaded to a server. This adapter does not open a network connection to Suricata/Zeek; export files from your own authorized sensor and import them manually.

Hardening checklist

  • Start with default deny, then open only the ports the service needs.
  • Limit admin ports such as SSH (22) to a trusted range or a VPN.
  • Never expose database ports such as 3306 to the internet.
  • Log dropped packets and review the logs for repeated sources.
  • Rate-limit login attempts to slow brute-force attacks.
  • Review rules every few months and delete the ones nobody can explain.
Packet Gate is a teaching simulator. It matches on protocol, source/destination IPv4 or CIDR, destination port and the selected connection-state label. Its state labels are supplied test metadata, not kernel connection tracking. This simulator does not send live traffic. Only run real scans or tests on systems you own or have permission to test.
